## 1. 先把五个问题摆在首位

### 问题 1：现在合个改动为什么都要找总控？

**因为三个 GitHub 开关没开**，跟代码无关：
1. ver3 没有分支保护——没有“必须 PR、必须 CI 绿”的硬规矩
2. CODEOWNERS 是空壳——里面是中文姓名不是 GitHub 账号，PR 无法自动派给负责人审批
3. 全员共用 `Developer` 账号——git 历史看不出谁改的，机器无法按人授权

**结果**：每个人的改动都堆到总控人工合并，总控成了唯一的“人肉门禁”，合并排队、集体调试。

> 解法不是“总控更努力合并”，而是把门禁交给机器（见第 3 节）。总控动作量：GitHub 里点 10 分钟设置。

### 问题 2：文件到底乱在哪？

**骨架已经不乱了**（ver3 六批次重构已完成）：前端 `features/` 五域、后端 `services/ai/` 包、
`core/` 公共层、`api/` 按域拆分都在位。**剩下的“乱”集中在 4 个具体点**：

| 点 | 现状 | 后果 | 处置 |
|---|---|---|---|
| ModelEditor.vue | 3445 行单文件，四个 Tab 挤一起 | 钱鸣改任何小功能都碰同一文件 | 本 Sprint 拆四 Tab（1 天） |
| FloorPlan.vue | 2855 行 | 看板改动风险大 | 拆组合式函数（1 天） |
| useExprEval | 双实现并存（平台版/模型组版） | 编辑器调通≠生产动画正确 | 合并为一套（1 天） |
| MachineManagement | 归属没定 | 边界文档里的真空 | **本次会议拍板归属** |

### 问题 3：“改完上传就能直接用”现实吗？

**现实，而且机制已经具备**——但“能用”的前提是机器先验过，不是人肉先看过：
- 新功能在自己目录改 → push feature 分支 → CI 自动跑（后端 pytest + 前端 build + 六机台 SVG 校验）
- **CI 绿 = 可以自合；CI 红 = 谁提谁修**，集成问题在合并前被拦住，不需要约集体调试
- 新机型甚至不用改注册代码：deriver 文件 `import.meta.glob` 自动发现，放对文件就生效

### 问题 4：怎么“随时合并、随时拆分”？

- **随时合并**：模块间只通过公共层的稳定接口通信；自己目录内的改动 CI 绿即自合，一天合十次也不影响别人
- **随时拆分**：新模块 = 沿边界加目录（新机台三件套 / 新 AI 工具注册 / 新页面一条路由）；
  下线模块 = 删自己的目录，内核不动。**模块是“可拔插资产”，不是“内核分支”。**

### 问题 5：这套规矩怎么保证不退化成口头约定？

**四条机器防线**（目前只通了 CI 一条，其余三条本次会议后通电）：

| 防线 | 机制 | 状态 |
|---|---|---|
| 合并门禁 | ver3 分支保护：PR + CI 必须绿 | ❌ 待总控开启 |
| 自动派审 | CODEOWNERS 按目录派给负责人 | ❌ 待收齐账号 |
| 身份可溯 | 每人独立 GitHub 账号，停用共用 Developer | ❌ 待全员配合 |
| 自动回归 | CI：pytest + build + 六机台校验（E2E 下阶段进 CI） | ✅ 已建 |

## 3. 宣布：以后就按这个规则提交（四类改动四种走法）

```
A. 只改自己目录     feature/xxx → PR → CI 绿 → 自己点合并      不找任何人
B. 要改别人目录     同上，但 PR 由该目录 owner 批准              机器自动派单
C. 碰公共层/core    PR 写清影响面 → 洪佳琪批准                    不找总控
D. 线上紧急修复     [hotfix] 当天合，24 小时内补测试              事后知会
```

**公共层清单（C 类，改动必须洪佳琪批准）**：
`main/config/database/models/schemas.py`、`core/*`、`services/{security,cache,realtime,perf,time_utils}.py`、
前端 `api/core.js`、`stores/*`、`router/*`、`package.json`、CI 配置。

**纪律**：公共层只加不改语义；改接口签名必须全仓 grep 调用点。

## 6. 三条铁律（写进团队共识，给会议收尾用）

1. **主干永远绿**：ver3 任何时候拉下来能一键启动、六机台可演示；CI 红是提 PR 的人的责任
2. **边界即分工**：自己目录自由，别人目录协商，公共层审批——由 CODEOWNERS 机器守护，不靠自觉
3. **一切可重建**：新机台/新环境靠脚本重建（15 分钟），不可重建数据（量产库/AI 配置）每日备份

> 量产策略一句话：**拒绝大爆炸切换**——影子运行 2~4 周（只读零影响）→ VPO 单台正式（跑一个完整班次）→ 横向铺开。
