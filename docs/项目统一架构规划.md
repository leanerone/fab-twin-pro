## 一、项目定位与边界

### 1.1 平台定位
**数字孪生可视化配置平台** — 专注于机台2D/3D模型的可视化呈现、动作匹配配置、历史回放与实时演示。

### 1.2 系统边界
| 职责 | 负责方 | 说明 |
|------|--------|------|
| RV资料接收与处理 | EAP/前置系统 | 可通过 WinForm 模拟器测试驱动 |
| 数据持久化（历史/实时） | Oracle/DB | 本平台读写（写入模拟数据，读取展示） |
| 2D/3D模型制作 | 建模工具/设计 | 本平台提供配置与接入规范 |
| 动作匹配配置 | 本平台 | 事件 → 部件动作的可视化配置 |
| 可视化展示 | 本平台 | 机台详情、事件回放、数据面板 |
| AI对话/MCP | 本平台 | Lot追溯、告警分析等 |

### 1.3 数据流
```
EAP/RV → 标准化事件 → DB ← 本平台（读写）
                          ↓
                    DB轮询服务 (db_poller)
                          ↓
                    WebSocket实时推送
                          ↓
                    前端可视化渲染

WinForm模拟器 → DB(DT_EVENT_RAW/CUR) → DB轮询 → 前端
```

## 三、PODOPENER 业务架构

### 3.1 业务流程全景

```
┌─────────────────────────────────────────────────────────────┐
│                    PODOPENER 业务流程                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌───────── PACKING（穿入）14步 ─────────┐                    │
│  │  1.POD_PLACED    → POD放置到位       │                    │
│  │  2.COMPLETED_PORT_LOCK → 端口锁定    │                    │
│  │  3.READ_BATTERY  → 读电池状态        │                    │
│  │  4.READ_TAG      → 读RFID标签        │                    │
│  │  5.BATCH_INFO_FROM_ECUI → 获取批次   │←─── HOST事件       │
│  │  6.OPEN_POD      → 开POD盖           │                    │
│  │  7.REACH_STAGE   → 机械臂到平台      │                    │
│  │  8.UI_CONFIRM    → 操作员确认        │←─── HOST事件       │
│  │  9.CLOSE_POD     → 关POD盖           │                    │
│  │ 10.ACK_UI_DOUBLECHECK → 二次确认     │←─── HOST事件       │
│  │ 11.REACH_POS     → 机械臂到位        │                    │
│  │ 12.WRITE_TAG     → 写RFID标签        │                    │
│  │ 13.COMPLETED_PORT_UNLOCK → 端口解锁  │                    │
│  │ 14.POD_REMOVED   → POD移走           │                    │
│  └──────────────────────────────────────┘                    │
│                        ↓ (同一张Cassette)                      │
│  ┌───────── UNPACKING（脱出）6步 ──────────┐                    │
│  │  1.UI_CONFIRM    → 操作员确认        │                    │
│  │  2.CLOSE_POD     → 关POD盖           │                    │
│  │  3.REACH_POS     → 机械臂到位        │                    │
│  │  4.WRITE_TAG     → 写RFID标签        │                    │
│  │  5.COMPLETED_PORT_UNLOCK → 端口解锁  │                    │
│  │  6.POD_REMOVED   → POD移走           │                    │
│  └──────────────────────────────────────┘                    │
│                                                             │
│  报警事件（随机插入流程中）：                                   │
│  - 9004 POD NOT FOUND [crit]                                │
│  - 0201 PORT LOCK FAIL [crit]                               │
│  - 9003 POD DOOR NOT LOCKED [warn]                          │
│  - 20011 TAG READ FAIL [warn]                               │
│  - 0411 DOOR OPEN TIMEOUT [info]                            │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 双模式实时驱动架构

```
┌─────────────────────────────────────────────────────────────┐
│                    实时数据驱动层                              │
├──────────────────────────┬──────────────────────────────────┤
│     模拟器模式（内部）      │     DB轮询模式（外部）            │
├──────────────────────────┼──────────────────────────────────┤
│                          │                                  │
│  services/simulator.py   │  外部系统写入DB                   │
│  主动生成事件             │  - WinForm模拟器                 │
│  写入DT_EVENT_RAW        │  - EAP/RV系统                    │
│  写入DT_EVENT_RAW_CUR    │  - 测试工具                       │
│                          │                                  │
│            ↓             │            ↓                     │
│    WebSocket 直接推送     │  services/db_poller.py           │
│    (原有逻辑)            │  每秒轮询DT_EVENT_RAW            │
│                          │  发现新事件 → WebSocket推送       │
│                          │                                  │
└──────────────────────────┴──────────────────────────────────┘
                              ↓
                        前端Vue3组件
                        （事件动作映射驱动动画）
```

### 3.3 事件动作映射规范

**PODOPENER事件 → 前端状态映射表**：

| 事件名称 | 动作类型 | 状态更新 | 动画效果 |
|---------|---------|---------|---------|
| POD_PLACED | podPlace | placed=true | POD显示在Port位置 |
| COMPLETED_PORT_LOCK | podLock | locked=true | 锁定图标亮起 |
| READ_BATTERY | signalBlink | 信号闪烁 | 电池状态读取动画 |
| READ_TAG | tagScan | scanActive=true | 扫描线动画 |
| BATCH_INFO_FROM_ECUI | uiConfirm | 批次信息显示 | UI确认弹窗 |
| OPEN_POD | podDoor | doorOpen=true | POD盖打开动画 |
| REACH_STAGE | robotMove | robotAtStage=true | 机械臂移动到平台 |
| UI_CONFIRM | uiConfirm | 状态更新 | 操作员确认提示 |
| CLOSE_POD | podDoor | doorOpen=false | POD盖关闭动画 |
| ACK_UI_DOUBLECHECK | uiDoubleCheck | 状态更新 | 二次确认提示 |
| REACH_POS | robotMove | robotAtStage=false | 机械臂回到原位 |
| WRITE_TAG | tagWrite | signalActive=true | 写入信号闪烁 |
| COMPLETED_PORT_UNLOCK | podLock | locked=false | 锁定图标熄灭 |
| POD_REMOVED | podPlace | placed=false | POD消失 |

### 4.2 核心设计原则

1. **配置驱动，而非代码驱动**：新机台型号接入无需改代码，通过配置完成
2. **渲染与数据分离**：可视化引擎不直接依赖数据源，通过统一数据模型对接
3. **2D/3D统一规范**：同一套部件ID、同一套事件动作映射，2D/3D双视图
4. **渐进式接入**：从单机型深度定制 → 多机型配置化 → 全平台标准化
5. **双模式实时驱动**：内部模拟器 + 外部DB写入，满足演示和生产需求

## 八、风险与建议

### 8.1 主要风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 前端动画与DB事件联动不顺畅 | 中 | 演示效果打折扣 | 优先保证PODOPENER 2D视图动画流畅 |
| WinForm用tkinter不够专业 | 低 | 用户体验 | 可快速用C#重写WinForm版本 |
| 配置化程度不足，新机台仍需改代码 | 中 | 平台价值打折扣 | PODOPENER验证配置化可行性 |
| EAP真实数据接入不确定 | 中 | 生产环境受限 | 模拟器+WinForm双兜底 |

### 8.2 关键建议

1. **先跑通一条线**：PODOPENER → 配置化 → 平台接入，跑通完整链路再复制
2. **配置优于编码**：所有新功能先想"能不能配置化"，再考虑硬编码
3. **数据驱动演示**：用模拟器生成真实感数据，比空架子有说服力
4. **双模式并行**：模拟器和DB轮询都保留，满足不同场景需求
5. **重视测试**：每个功能开发后立即测试，避免积累问题
