## ver2.8.2（2026-08-31）— 平面图区域/机台编辑三连修复 + 机台改名

### 功能概述
用户在平面图编辑模式实测发现三类问题：①新建区域报 500；②区域名称、颜色无法修改；③机台从平面图删除后无法重新添加。本次热修复一次性解决区域创建（Oracle 主键）、区域改名/改色 UI、机台删除后重新分配三个缺陷，并顺带补齐「机台改名」能力（选中机台后直接改名保存）。

### 缺陷根因与修复
| # | 缺陷 | 根因 | 修复 |
|---|------|------|------|
| Bug1 | 新建区域 POST /api/floors/{id}/areas 返回 500 | `floors.py` 用 `db.func.max()` 取最大 ID，但 SQLAlchemy Session 无 `.func` 属性 → AttributeError；且 Oracle 表 `FLOOR_AREAS.ID` 无 identity 列，原代码依赖自增 | `from sqlalchemy import func` + `func.max()` + 手动 `id = MAX(id)+1` |
| Bug2 | 选中区域无法改名 | `FloorPlan.vue` 选中区域只显示名称文本+删除按钮，无名称输入框；后端 `update_area` 其实已支持 name 字段 | 选中区域块改为「名称输入框 + 颜色选择器 + 💾保存 + 🗑删除」，新增 `saveAreaProps()` 调 `updateFloorArea` |
| Bug3 | 选中区域无法改色 + 新建区域无颜色选择 | 同上缺颜色选择器 | 选中区域加颜色选择器；新建区域表单加颜色选择器（切换类型自动套默认色可覆盖） |
| Bug4 | 机台从平面图删除后，用同一 ID 重新添加报 409「机台ID已存在」 | `delete_machine` 只置 `floor=None` 保留机台记录；`add_machine` 见 ID 存在即抛 409 | `add_machine` 改为：机台存在但 `floor=None` → 重新分配到当前楼层（更新 floor/坐标/name/model）；仅当已分配到**其它**楼层才报 409 |
| Feature | 机台无法改名 | 后端无改名端点（仅 external-link） | 新增 `PUT /api/floors/{floor_id}/machines/{machine_id}`（update_machine_info，floor_edit 权限，支持 name/process_type/line）；前端加 `editMachineName` 草稿 + `saveMachineName()` + 选中机台块加名称输入框+💾改名按钮 |

|------|------|

- 小版本：功能迭代或修复

## 变更类型

| 类型 | 含义 |
|------|------|
| `feat` | 新增功能 |
| `fix` | 缺陷修复 |
| `refactor` | 重构（不改变外部行为） |
| `docs` | 文档变更 |
| `chore` | 构建/依赖/配置 |
| `breaking` | 破坏性变更（不向后兼容） |
