## 0. 背景与问题诊断（来自 2026-11-05 分析）

现 AI 链路：前端双入口（悬浮球 / 机台详情面板）→ `/api/ai/chat(/stream)` → 路由链
（机台专属 Dify → admin n8n 指令 → OpenAI 兼容 LLM + Function Calling → Dify/hybrid → 本地规则引擎）。

核心痛点：
1. **工具/知识割裂**：走 Dify 时本地 12+2 工具失效，走本地 LLM 时 Dify RAG 失效 → 不智能的最大根因
2. **n8n 不稳定依赖**：承担 MCP 工具服务器（MES_LotInfo_Query）+ webhook 自动化两个职责，需可替换
3. **admin n8n 关键词误触发**（`middleware.py:900`）：导出/报表/批量/自动/推送 等常见词直通 n8n 绕过 LLM
4. **会话存内存**：重启失忆 + `self.sessions`/`_dify_conv_map` 无界增长
5. **路由不透明**：用户不知道回答来自哪个引擎，答得差没有一键重试
6. （附带）安全四项与前端加载性能，见 T6/T7

## 1. 任务清单（按施工顺序）

### T1 修复 admin n8n 关键词误触发 【预计 40min】
- 文件：`backend/modules/ai_assistant/services/middleware.py`（`_is_n8n_command`）
- 方案：三层收紧——①显式前缀 `n8n:` / `n8n：` 直接命中；②强匹配（动词+名词组合：导出…报表、生成…工单、推送…日报）；③模糊词（批量/自动/推送）在已配置 LLM 时**不再**直通 n8n，交给 LLM 工具路由
- 测试：新增 `tests/ai/test_n8n_command_gate.py`（用例：`n8n:导出报表`→触发；`帮我导出报警报表`→触发；`批量查一下告警`→不触发走 LLM；普通用户说导出→不触发）
- 回滚：单文件 revert

### T2 路由透明化 + 换引擎重答 【预计 60min】
- 后端：`/api/ai/chat` 与 `/chat/stream` 请求体新增可选 `force_provider`（`"dify"|"llm"|"local"`），
  命中时跳过机台专属路由按指定引擎执行；响应 final 帧已带 provider/provider_name（已有，不动）
- 前端：`AiAssistant.vue` 与 `AIFloatingBall.vue` 消息气泡 meta 区显示引擎徽标（provider_name）；
  回答失败或用户点"换个引擎再答"时带 `force_provider` 重发
- 测试：`tests/ai/test_force_provider.py`——force_provider=local 返回 answer 且 provider=local；流式同验
- 回滚：前端 revert + 后端参数可选不影响旧调用

### T3 会话持久化 + 内存上限 【预计 90min】
- 后端：新表 `AI_CHAT_SESSIONS(session_id VARCHAR2(64) PK, machine_id, messages CLOB, updated_at)`
  （幂等 DDL 加在 `ai_assistant` 模块 seeds；沿用既有建表风格）
- `middleware.py`：chat/chat_stream 读写时先查内存再查 DB；每轮落库；内存 `self.sessions` 加 LRU（MAX 200 会话）；
  `_dify_conv_map` 加上限 500（已有 7 天清理，再加运行时上限）
- 效果：后端重启后多轮上下文不丢；长运行内存有界
- 测试：`tests/ai/test_session_persist.py`——写两轮 → 直接 `ai_middleware.sessions.clear()` 模拟重启 → 第三轮仍引用上文；并发 300 假会话不超上限
- 回滚：新表独立，revert 代码即可

### T4 Dify 工具桥（REST 暴露 + OpenAPI 导出）【预计 120min】★性价比最高
- 后端：`modules/ai_assistant/routes/ai_tools_bridge.py`：
  - `GET /api/ai/tools`：列出全部工具（name/description/参数 schema）
  - `POST /api/ai/tools/{name}`：统一分发到 `TOOL_HANDLERS`（鉴权 required；SQL 工具沿用 sql guard 白名单）
  - `GET /api/ai/tools/openapi.json`：生成 Dify「自定义工具→OpenAPI-Spec」可直接导入的 3.1 规范
- 意义：Dify 应用导入此 schema 后即拥有全部本地数据工具 → 机台专属 Dify 与全局 Dify 不再缺数据能力
- 测试：`tests/ai/test_tools_bridge.py`——14 个工具逐个 POST 校验 200 与结构；schema 可被 jsonschema 校验；未带 token 401
