## 二、n8n 真实对接（已完成 ✅）

**安装方式**：npm 直装（无需 Docker）。位置 `E:\AI\fab-ai-services\n8n`，Node 20 便携版在 `E:\AI\fab-ai-services\node20`。
版本：**n8n 2.8.4**，端口 5678，账号 `admin@fabtwin.local / FabTwin#2026!N8n`。

**踩坑记录（四连坑，都有据可查）**：
1. Node 24 下 sqlite3 源码编译失败（无 VS Build Tools）→ npm 整体回滚 → **换 Node 20 走预编译产物**解决
2. n8n 2.x 的 owner/login 接口字段变化（firstName / emailOrLdapLoginId）
3. **Node 20 把 `localhost` 解析成 IPv6 `::1`**，而后端 uvicorn 只监听 IPv4 → 工作流内 URL 必须写 `127.0.0.1`（ECONNREFUSED ::1:8002）
4. n8n 的 HTTP Request 节点会把 JSON 数组响应**拆成多个 item**，Code 节点必须聚合 `$input.all()` 而不是取 first()

**两个真实工作流**（已激活）：
- `FabTwin 通用查询`：webhook `general_query` → 回显问题 + executionId
- `FabTwin 报警报表导出`：webhook `export_alarm_report` → **HTTP 反查 FabTwin API（Bearer 鉴权）→ Oracle 实时告警 → 聚合成结构化表格回传**

## 三、Dify 对接（待一次重启，步骤已备好）

Dify 是多服务 Linux 栈（API/Worker/Web/PostgreSQL/Weaviate/Nginx），**没有免 Docker 的 Windows 安装路径**。BIOS 虚拟化已开，差 WSL2 特性启用（必须重启）：

```powershell
# 1. 管理员 PowerShell（触发特性启用，需要重启一次）
wsl --install --no-distribution
# 2. 重启后安装 Docker Desktop（winget install Docker.DockerDesktop 或官网安装包）
# 3. 运行仓库自带脚本（Dify 0.10.3，Web 端口 8088）
powershell -ExecutionPolicy Bypass -File deploy\deploy_dify.ps1 -Action install
# 4. 浏览器开 http://localhost:8088 完成初始化 → 建应用 → 拿 API Key
# 5. 配置后端并测试：
```
