## 二、Git 工作流（每个人照做即可）

1. **用你自己的 GitHub 账号提交**。第一次配置（每台电脑一次）：
   ```bash
   git config --global user.name "你的名字"
   git config --global user.email "你的GitHub邮箱"
   ```
   ⚠️ 目前大量提交作者是共用的 "Developer"，从今天起禁止——出了问题查不到人，审核也没法按人分配。

2. **唯一主线是 `test3`**。开工先同步、再开自己的分支（名字格式 `名字-在做什么`）：
   ```bash
   git checkout test3 && git pull
   git checkout -b qianming-lam2300-修正     # 例
   ```

3. **只改自己分工表里的路径**。实在需要动别人的/公共的文件 → 在 PR 里写明原因，由对方 owner 审核。

4. **提 PR**（GitHub 网页上点，或 `gh pr create`）：填 PR 模板（改了什么/怎么自测的/碰到公共文件没有）。CI 自动跑三道检查，全绿才能合。

5. **合并规则**：
   - 只动自己目录 + CI 绿 → **自己合**，不用等别人；
   - 碰到别人目录 → 对方 owner 批准后合（CODEOWNERS 自动把他拉进审核）；
   - 碰到平台内核文件 → 洪佳琪批准后合。

6. **数据库变更一律走 `sql/` 脚本**，脚本进 PR。禁止只在数据库里改表、改配置——"在我机器上是好的"就是这么来的。

## 四、机制文件启用步骤（一次性，10 分钟）

1. 把 `CODEOWNERS` 里的 `@占位账号` 换成每人真实 GitHub 用户名（文件内有对照注释）。
2. GitHub 仓库 → Settings → Branches → Add rule：
   - Branch name pattern: `test3`
   - ✅ Require a pull request before merging
   - ✅ Require review from Code Owners
   - ✅ Require status checks to pass（选 `backend-tests`、`frontend-build`、`svg-motion-contract`）
3. Actions 页确认 CI 首跑全绿（首跑可能因环境差异需微调，见 ci.yml 注释）。
4. 建 GitHub Projects 看板，把每个 Sprint Goal 建成卡片指派到人（替代口头分工）。

## 五、常见问题

- **两个人要改同一个文件怎么办？** 说明该文件其实是"公共汇合点"，先在 Sprint Meeting 上决定它归谁，再挪目录（参考交接说明里 ai_middleware 的拆分计划）。临时先按 PR 顺序排队，后合的人 rebase。
- **CI 挂了但本地是好的？** 十有八九是忘了把新依赖写进 `backend/requirements.txt` 或新增了数据没走 `sql/` 脚本。
- **急修要直接上 test3？** 例外通道：总控（季世庆）可以在 PR 描述标注 `[hotfix]` 合并，事后当天内补齐自测证据。
