## 2. 部署与数据库迁移

### 2.1 前置检查

1. 备份目标库，并确认连接的是目标 PDB/service，而不是默认 SID。
2. 存量库先备份 `AI_CONFIGS` 等业务配置；不要在共享库直接运行会改写配置的 AI 全链测试。
3. 使用有建表、改列和建索引权限的目标账号执行迁移。先核对对象是否存在，再决定是否执行增量脚本。
4. `tests/run_init_sql.py` 使用固定本机 Oracle 连接参数，仅用于本机回归，**不是通用生产迁移工具**。目标环境应使用受控的 SQL*Plus/SQLcl 或 DBA 流程。

### 2.2 存量 Oracle 环境

在仓库根目录按顺序执行：

```powershell
sqlplus "<用户>/<密码>@<连接描述符>" @sql/v2.12_add_ai_conversations.sql
sqlplus "<用户>/<密码>@<连接描述符>" @sql/ver3_fix_platform_index_columns.sql
```

- `v2.12_add_ai_conversations.sql` 创建 `AI_CONVERSATIONS`、`UK_AI_CONV_SESSION` 和 `IDX_AI_CONV_UPDATED`，可幂等复跑。后端 `init_db()` 不会自动补建该表。
- `ver3_fix_platform_index_columns.sql` 收敛八个 ORM 查询列至 `VARCHAR2(255)`，再创建四个平台索引。每列先检查实际 `LENGTHB`；存在超过 255 字节的数据会中止，**不会静默截断**。
- 四个索引分别创建，仅忽略已存在或等价索引；其他数据库错误仍会抛出。不要以“应用启动未报错”替代迁移结果检查。
- 全新环境先按目标方案执行 `sql/init_oracle_db.sql` 或 `sql/init_oracle_aqua.sql`，再补执行 AI 会话增量脚本；两个初始化脚本的查询列宽已与本次迁移对齐。

迁移后至少核对：

```sql
SELECT table_name FROM user_tables WHERE table_name = 'AI_CONVERSATIONS';
SELECT index_name FROM user_indexes
 WHERE table_name IN ('AI_CONVERSATIONS', 'MACHINE_EVENTS', 'ALARMS', 'OHT_POSITIONS', 'LOTS')
 ORDER BY table_name, index_name;
```

完成迁移后再启动后端、构建前端。受保护 API 使用签名 Bearer token；事件注入使用 `FABTWIN_INGEST_API_KEY` 对应的 `X-API-Key`，外部旧集成需同步确认鉴权配置。
