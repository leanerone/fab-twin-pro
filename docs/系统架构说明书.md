## 一、项目概述

### 1.1 背景

FabTwin Pro 是面向半导体晶圆制造厂的机台层数字孪生平台，对接 EAP/TIBRV 实时事件流与 Oracle 历史数据，将物理机台的运行状态、工艺流程、告警信息以 2D/3D/Canvas 可视化方式实时呈现，并支持任意时间点回放、AI 自然语言查询、多 Provider 大模型接入、机台外链跳转、模型文件上传管理。

截至 ver2.6.1 已完成 **三种核心机型** 的端到端接入：
1. **VPO-2200 PODOPENER（开盖机）**：SVG 2D + Canvas 伪 3D 双视图，14+6 事件动画，7 天历史回放，AI Lot/告警查询
2. **TEL DRM UNITY**：Three.js 精细 3D 模型，7 步工艺动画，状态灯
3. **OXE 刻蚀机（主力量产机型）**：Canvas 2D 自研引擎 Vue 化，3 Chamber + 2 PORT Wafer Map，9 天历史数据回放，3 个 OXE 专用 AI 工具

### 1.2 目标（ver2.6.x 已达成 + ver3.0 规划）

| 维度 | ver1.0 目标 | ver2.6.1 现状 | ver3.0 规划 |
|------|------------|-------------|------------|
| 可视化 | 一套代码支持 2D/3D/2.5D | ✅ 已支持 5 种渲染模式（SVG/Canvas伪3D/Three.js/Canvas2.5D/Canvas OXE） | 3D LOD 优化 |
| 实时性 | DB 轮询 + WS，延迟 ≤1s | ✅ PODOPENER ≤1s，OXE 1 秒 DB 轮询 | TIBRV 桥接延迟 ≤500ms |
| 配置化 | 新机型 JSON 配置即可接入 | ✅ Motion JSON + SVG 双通道导入，动画配置数据库化 | 可视化拖拽编排 |
| 回放能力 | 7 天 × 08-20 × 6 档倍速 | ✅ OXE 扩展至 9 天（08-06~08-14），6 档倍速 + 时间戳二分查找跳转 | 30 天 + 分页查询 |
| AI 辅助 | Lot/告警/状态 + 回放跳转 | ✅ 多 Provider + 专用工具 + 动态快捷问题 + 全链路日志 | 智能异常诊断 + RAG 知识库 |

### 1.3 核心价值

1. **生产监控透明化**：把抽象的 RV 报文变成可见的动画与状态（OXE Wafer Map 实时显示每片晶圆位置）
2. **故障回溯高效化**：点击告警/事件/Lot 即可跳转到对应时刻，秒级还原现场（AI 返回 jump_timestamp + jump_machine_id）
3. **新机型接入标准化**：通过 Motion JSON + SVG 双通道导入，支持部件高亮联动、多选/框选/组合，普通工程师可完成配置
4. **AI 助手平民化**：4 种 AI Provider 模式（local/openai/dify/hybrid）+ 智谱 GLM 默认 + 本地规则引擎兜底，无需外网即可查询
5. **生产系统无缝衔接**：支持机台详情页 iframe 嵌入第三方生产系统外链，实现「一个平台管所有」

### 2.3 数据库（ver2.6.1 最新：27 张表 + 扩展字段）

- **Oracle 10g/11g/19c**（Thick mode：需 ORACLE_CLIENT_DIR 环境变量指向 64-bit Oracle Client 19c+；ORACLE_DSN_TYPE=sid 对应 10g/11g）
- **27 张表**：5 张 RV 对齐表 + 15 张业务扩展表 + 4 张权限表 + 3 张 AI 专用表
- 切换方式：环境变量 `DB_TYPE=sqlite|oracle`
- **数据库升级策略**：手动 SQL 脚本（ORM 自动建表已禁用，AI 表通过 `create_ai_tables.sql` 手动创建）

### 2.4 3D / 可视化引擎矩阵（ver2.6.1 最新）

- **Three.js 0.160** 直接 WebGL 渲染 → TEL DRM UNITY 精细 3D 模型
- **PODOPENER Canvas 伪 3D 投影** → 箱体拼装，无需 Blender 建模
- **OXE 自研 Canvas 2D 引擎** → Vue 组件化（MachineOxeView.vue），3 Chamber + 2 PORT + Wafer Map 面板 + 机械臂动画
- **模型编辑器 ModelEditor.vue** → 箱体拼装（box/cylinder）+ SVG 导入预览 + Motion JSON 导入 + 录制调教 + 多选/框选/组合
- **MotionPreview.vue 动画预览组件** → SVG 内联渲染（fetch + v-html）+ 事件触发按钮 + 7 类动作（offset/rotate/scale/opacity/visibility/flash/color）+ when 条件分支

### 2.5 AI 中间适配层（ver2.6.1 重大升级）

- **AI Provider 抽象**：`local` / `openai` / `dify` / `hybrid` 四种模式，中间层统一请求/响应格式
- **Provider 配置持久化**：`ai_configs`（默认设置）+ `ai_provider_configs`（多Provider配置：name/base_url/api_key/model/is_active/is_default）
- **Token 使用统计**：`ai_usage_logs` 表记录每次调用 input_tokens/output_tokens/total_tokens/execution_log，支持按 Provider/日期聚合
- **OpenAI 兼容协议**：自动识别 Base URL 版本号后缀（/v1 /v4 等），智谱 GLM 正确拼接为 `/v4/chat/completions`（修复 ver2.3.1 的 `/v4/v1` 重复 bug）
- **Function Calling 降级重试**：不支持 tools 的 Provider（如部分私有模型）捕获错误后自动移除 tools 二次请求
- **OXE 专用 AI 工具 ×3**：`get_wafer_flow`（晶圆流向推算）/ `get_chamber_status`（3 Chamber 状态推算）/ `get_oxe_lot_summary`（Lot 加工汇总）
- **本地规则引擎兜底**：Lot 查询、机台状态、告警统计、温度趋势、产量统计、异常检测（6 大类）
- **Dify + n8n 编排**：Dify DSL 模板 + n8n 5 个工作流模板（Oracle/MES/RCMS/FDC/异常通知），待服务器部署验证
- **Whisper ASR**：本地语音输入，HF 国内镜像

### 2.6 部署（ver2.6.1 生产级）

- **deploy/ 目录 9 个脚本**：`deploy.bat` / `start-dev.bat` / `one_click_deploy.bat` / `package_offline.bat` / `deploy_iis_nt_final.bat` / `init_db.bat` / `start_iis.ps1` / `start_backend.ps1` / `start_direct.ps1`
- **IIS 生产部署**：web.config 三条 rewrite 规则（APIProxy / WSProxy / **UploadsProxy**，SpaFallback 排除 `/uploads/` 路径）
- **IIS WebSocket**：必须通过 appcmd 在站点级启用（不能在 web.config 中配置）
- **Vite preview**：vite.config.js 显式 proxy（/api /ws /uploads → 后端 8002）
- **内网兼容**：依赖安装失败不阻断，Redis 不可用回退内存，Oracle 不可用回退 SQLite

#### 4.1.6 配置层：数据库化改造（ver2.0 升级，不再依赖本地 JSON）

> **核心决策**：动画配置从 `frontend/src/configs/machine-animations/podopener.json` 静态文件迁移到数据库 `machine_model_configs.animation_config_json` 字段，支持运行时热更新（无需重新构建前端）。

**Motion JSON 格式（schema_version ≥ 1.1）**：
```json
{
  "schema_version": "1.1",
  "machine_type": "AMAT-TEST-001",
  "parts": [
    {"part_id": "ARM_2", "part_name": "机械臂", "part_type": "arm"}
  ],
  "motions": {
    "CHAMBER_START": [
      {"target": "ARM_2", "action": "rotate", "duration_ms": 1500, "params": {"angle": 45}}
    ]
  },
  "flows": {
    "default": [{"phase": "...", "event_to_phase": {}, "duration_ms": 2000}]
  }
}
```

**兼容策略**：UI 上同时支持 Motion JSON 新格式（parts 数组）和旧格式（targets 对象），`extractSvgPartsToTargets` 已存在则更新 part_type/part_name。

### 4.7 OXE 机台接入平台专题（ver2.2 → ver2.4 核心新增）

> 详见 `docs/OXE接入指南.md`，此处仅提炼架构要点。

#### 4.7.1 关键架构决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 实时画面方案 | 平台内 Canvas + DB 轮询（1 秒间隔） | 不接收 RV 消息，数据由量产系统直接写入 Oracle；轮询 DB 最新即可 |
| Canvas 引擎部署方式 | 从独立 oxe.html **迁移为 Vue 组件 MachineOxeView.vue** | 统一架构，复用平台 KPI/回放/AI 控件，避免 iframe 嵌套通讯问题 |
| 数据源 | 复用 DT_EVENT_RAW（parse_status='PARSED' 过滤，排除 ERROR 状态） | 用户明确"先用现有表"，不依赖实时账务表 DT_EVENT_REALTIMELOT |
| OXE tool_id 匹配策略 | 前缀匹配（OXE-61 → OXE-T61/OXE-T61A/OXE-61 全部命中） | 量产 DB 中 OXE 机台 tool_id 带 T 前缀变体 |
| 时间戳兜底策略 | `COALESCE(event_ts_utc, received_ts_utc)` | RV 报文不带事件时间时，bridge.py 写 received_ts_utc，event_ts_utc 可能 NULL |
| 历史数据查询量 | 单次 limit = 10000，配合 9 天日期（08-06~08-14）分页 | 避免 OXE 数据截断（ver2.4 从 2000 提升） |

#### 4.7.2 事件 → 晶圆状态推算逻辑（OXE AI 工具核心）

通过 **5 种关键事件名**（量产需验证：WaferLoaded/WaferUnloaded/Start/PS/PE）推算：

| 事件名 | 含义 | 推算结果 |
|--------|------|---------|
| WaferLoaded（含 payload.slot） | 机械臂把某片晶圆装入 Chamber | Chamber→busy，Wafer→该 Chamber 加工中，slot→lot_id+slot 编号 |
| Start / PS | 工艺开始 / 工艺步骤启动 | Chamber→processing 状态，开始计时 |
| PE | 工艺步骤结束 | Chamber→still processing，累计加工片数 |
| WaferUnloaded | 晶圆从 Chamber 取出 | Chamber→idle，Wafer→下一站/返回 Cassette |

#### 4.7.3 URL query 参数驱动回放（SPA 路由处理）

- URL 格式：`/machine/OXE-61?date=2026-08-08&mode=playback`
- `onMounted` 读取 `route.query.date` 和 `route.query.mode`，自动设置 `playbackDate` → `switchToPlayback()`
- `watch(route.query)` 监听 SPA 切换 query（同组件不重新挂载），变化时自动重新加载对应日期历史数据

### 5.2 历史回放（OXE 专用）

```
1. 用户进入机台详情页 OXE-61 ?date=2026-08-14&mode=playback（URL 携带参数）
2. onMounted 读取 route.query.date → playbackDate=2026-08-14
3. switchToPlayback() → GET /api/oxe/history-events?machine_id=OXE-61&date=2026-08-14
   → 后端：COALESCE(event_ts_utc, received_ts_utc) BETWEEN 日期范围
   → WHERE parse_status='PARSED'
   → ORDER BY event_ts_utc ASC LIMIT 10000
4. 返回 185 条事件（每天）→ HistoryReplay 渲染 24h 柱状时间轴
5. **自动 seek(0)**：从时间戳最小事件开始往前推一遍，初始化 Pod/Port/机械臂/Wafer Map 到位
   （用户刚切回放不看到空白画面）
6. 用户点击某事件柱 → 二分查找找到最近事件索引 → cursor 跳到对应时间戳
7. 播放循环按 speed（0.5x–16x）推进 cursor
8. scaleDuration(ms) = ms / speed（最低 30ms），所有动画 duration 包装此函数确保倍速同步
9. 每个事件按 cursor 时间触发 applyEvent → 机械臂/Wafer Map/Chamber 状态同步更新
10. watch(route.query) 处理 SPA 切日：date 变化时重新走 3-9 步骤
```

## 七、关键设计决策（ver2.6.1 补充）

### 7.1 配置驱动而非代码驱动 → 升级为**数据库化驱动**（ver2.0）
ver1.0 用静态 JSON 配置，ver2.0 迁移到 `machine_model_configs.animation_config_json` 字段，运行时热更新无需重新构建前端。

### 7.2 AI 配置必须持久化到数据库（ver1.3，硬约束）
环境变量只作为兜底，真实配置存储在 `ai_provider_configs` 表。原因：IIS 部署重启服务时，如果只靠 env 变量 + 内存，配置会丢失（用户踩过坑）。

### 7.3 Oracle 10g/11g 必须用 Thick 模式 + SID（ver2.2，硬约束）
10g/11g 不支持 Thin 模式 service_name，必须：
- 设 `ORACLE_CLIENT_DIR` 环境变量指向 64-bit Oracle Client 19c+
- 设 `ORACLE_DSN_TYPE=sid`（12c+ 用 service_name）
- deploy 脚本必须**显式传所有 Oracle 连接参数**（host/port/service/user/password）通过 env 变量

### 7.4 OXE 机台 AI 只能用默认 Provider（详情页），悬浮球支持切换（ver2.4 决策）
- 详情页 AI 场景稳定（用户一直在看该机台），不需要切 Provider，避免混乱
- 悬浮球是全局通用入口，用户可能测试不同模型（GLM vs DeepSeek vs GPT），支持临时切换合理

### 7.5 模型文件按 file_type 分槽存储（ver2.5.3 修复）
之前单 `current_file` 字段导致 SVG+JSON 同时上传时后者覆盖前者。改为 5 个独立槽位：`current_svg / current_json / current_glb / current_html / current_file`（兼容旧前端）。

### 7.6 SVG 预览改用内联渲染（fetch + v-html）替代 `<object>`（ver2.5.4 决策）
`<object>` 标签在 IIS 部署环境兼容性差（加载失败 → fallback iframe → SpaFallback 返回 index.html → 嵌套进主页看板），内联渲染 100% 可控。

### 7.7 IIS UploadsProxy 必须在 SpaFallback 之前（ver2.5.5 修复）
之前把 `/uploads` 路径漏掉，SVG 文件请求被 SpaFallback 拦截返回 HTML，导致前端校验「返回内容不是 SVG」报错。

### 7.8 机台外链 URL 双重协议补全（ver2.6.1 决策）
用户习惯填 `www.baidu.com` 不带协议。两处补全保证：① 保存时 FloorPlan.vue 自动加（写 DB 时就正确）② 显示时 externalFrameUrl 计算属性兜底（即使存量 DB 数据不规范也能显示）。
