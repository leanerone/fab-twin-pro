> 适用范围：半导体机台数字孪生平台（PODOPENER / TEL DRM UNITY / OXE 多机型）

## 一、项目概述

### 1.1 背景

FabTwin Pro 是面向半导体晶圆制造厂的机台层数字孪生平台，对接 EAP/TIBRV 实时事件流与 Oracle 历史数据，将物理机台的运行状态、工艺流程、告警信息以 2D/3D 可视化方式实时呈现，并支持任意时间点回放、AI 自然语言查询。

ver1 已完成第一个机型 **VPO-2200 PODOPENER（开盖机）** 的端到端接入：从 SVG 2D 视图、Canvas 3D 视图，到 14+6 个 PACKING/UNPACKING 事件的动画驱动、7 天历史回放、WinForm 模拟器驱动、统一配置层与调试面板。

### 1.2 目标

| 维度 | 目标 |
|------|------|
| 可视化 | 一套代码同时支持 2D / 3D / 2.5D 等角三种渲染模式，按机型自动切换 |
| 实时性 | DB 轮询 + WebSocket 推送，事件延迟 ≤ 1 秒 |
| 配置化 | 新机型接入只需 JSON 配置 + 资源文件，不改业务代码 |
| 回放能力 | 任意日期 08:00–20:00 历史数据回放，0.5x–16x 倍速 |
| AI 辅助 | 自然语言查询 Lot/告警/状态，并支持回放跳转 |
| 部署友好 | Windows 内网一键 `deploy.bat` 部署，Oracle/SQLite 无缝切换 |

### 1.3 核心价值

1. **生产监控透明化**：把抽象的 RV 报文变成可见的动画与状态。
2. **故障回溯高效化**：点击事件即可跳转到对应时刻，秒级还原现场。
3. **新机型接入标准化**：通过 `podopener.json` 等配置文件 + 命名约定，普通工程师也能完成新机型接入。
4. **AI 助手平民化**：本地 Whisper ASR + 规则引擎兜底，无需外网即可语音查询。

## 二、技术栈

### 2.1 前端

| 类别 | 技术 | 版本 | 用途 |
|------|------|------|------|
| 框架 | Vue 3 | 3.4 | 组合式 API + `<script setup>` |
| 构建 | Vite | 5.x | dev/build，`import.meta.glob` 预加载配置 |
| 状态 | Pinia | 2.x | app/model/auth 三个 store |
| 路由 | Vue Router | 4.x | hash 模式，4 条路由 |
| UI 库 | Element Plus | 最新 | 通用组件 |
| 3D | Three.js | 0.160 | WebGL 3D 渲染（TEL DRM UNITY 精细模型） |
| 2D | SVG + Canvas | 原生 | PODOPENER 2D 正视图 / Canvas 3D 投影 / 2.5D 等角 |
| 通信 | WebSocket | 原生 | 实时事件推送，指数退避重连 |

### 2.2 后端

| 类别 | 技术 | 版本 | 用途 |
|------|------|------|------|
| 框架 | FastAPI | 最新 | 异步 API + 自动 OpenAPI 文档 |
| ORM | SQLAlchemy | 2.0 | 24 张表 ORM |
| 数据库 | Oracle | 19c | 生产数据库（PDB: ORCLPDB） |
| 数据库 | SQLite | 内置 | Demo/离线兜底 |
| 缓存 | Redis | 6+（可选） | 状态/KPI 缓存，不可用时回退内存 |
| ASR | faster-whisper | tiny 默认 | 本地语音识别，HF 国内镜像下载 |
| AI | OpenAI 兼容 / Dify / n8n | 可选 | GLM-5.2、GPT 系列、私有模型 |

### 2.3 数据库

- **Oracle 19c**（PDB `ORCLPDB`，用户 `fabtwin`）
- 24 张表：5 张 RV 对齐表 + 19 张扩展表（含 4 张权限表）
- 切换方式：环境变量 `DB_TYPE=sqlite|oracle`

### 2.4 3D 引擎

- **Three.js 0.160** 直接 WebGL 渲染
- PODOPENER 采用 **箱体拼装模型**（Canvas 2D 伪 3D 投影），无需 Blender 建模
- TEL DRM UNITY 采用代码生成的精细 3D 模型（待替换为 GLB）
- 模型编辑器 `ModelEditor.vue` 提供箱体拼装能力

### 2.5 AI 中间适配层

- **AI Provider 抽象**：`local` / `openai` / `dify` / `hybrid` 四种模式
- **本地规则引擎兜底**：Lot 查询、机台状态、告警统计、温度趋势、产量统计、异常检测
- **OpenAI 兼容协议**：默认对接 GLM-5.2，可切换 GPT/本地私有模型
- **Dify + n8n 编排**：Dify 管 LLM/RAG，n8n 管工具编排（Oracle/MES/RCMS/FDC）
- **Whisper ASR**：本地语音输入，HF 国内镜像 `hf-mirror.com`

### 2.6 部署

- **deploy.bat**：4 步一键部署（环境检查 → 后端 venv → 前端 build → 启动）
- **start-dev.bat**：开发模式启动
- **init_db.bat / create_user.bat**：数据库初始化与建用户
- 内网兼容：依赖安装失败不阻断，Redis 不可用回退内存

### 4.4 3D 引擎

#### 4.4.1 渲染技术矩阵

| 视图模式 | 渲染技术 | 适用机型 | 组件 |
|---------|---------|---------|------|
| `threejs` | Three.js WebGL | TEL DRM UNITY 精细模型 | `MachineModel3D.vue` |
| `isometric` | Canvas 2D 等角投影 | OXE 刻蚀机 | `MachineIsoView.vue` |

| `svg` | SVG | 通用 2D 原理图 | `MachineModel2D.vue` |

#### 4.4.2 箱体拼装模型

PODOPENER 3D 视图采用 **箱体拼装** 策略，无需 Blender 建模：

- 每个部件（POD 外壳、锁扣、晶舟、扫描线、信号灯、UI 面板、左右手）由基本几何体（box / cylinder / plane）拼装
- 部件按 `targets` 配置中的 `view_3d` 字段命名（如 `podShellGroup` / `latchGroup`）
- 通过 Three.js Group 的 `userData` 标识部件，配置层按 key 查找
- 动画通过修改 Group 的 `position` / `rotation` 实现

`ModelEditor.vue` 提供箱体拼装的可视化编辑能力（ver2 完善）。

### 4.5 事件-动画统一配置层（M1+M2+M3）

#### 4.5.1 M1：配置层（`frontend/src/configs/machine-animations/` + `composables/useAnimationConfig.js`）

**目标**：把原本硬编码在 `useEventActionMapping.js` 中的事件→阶段→动画映射，提取为 JSON 配置文件，支持 2D/3D 视图共用。

**核心文件**：

1. `podopener.json` —— PODOPENER 配置
   - `machine_type` / `version` / `description`
   - `flows.PACKING` / `flows.UNPACKING`：阶段序列 + `event_to_phase` 映射
   - `animations`：动画原语库（`pod.enter` / `latch.lock` / `scan.blink` 等 14 个）
   - `targets`：部件绑定（`view_2d` SVG id + `view_3d` Group 名）
2. `_schema.json` —— JSON Schema 校验
   - 5 个顶级必填字段：`machine_type` / `version` / `flows` / `animations` / `targets`
   - `action` 枚举：`translate` / `rotate` / `scale` / `flash` / `visibility` / `color` / `scan` / `signal`
   - `easing` 枚举：`linear` / `easeInOut` / `mechanical` / `easeOut` / `easeIn`
3. `useAnimationConfig.js` —— 加载器
   - `import.meta.glob('../configs/machine-animations/*.json', { eager: true, as: 'raw' })` 预加载
   - 内置 `validateConfig` 轻量校验
   - API：`loadConfig` / `getPhaseByEvent` / `getAnimation` / `getTarget` / `getPhases` / `getEventMap` / `inferFlowByEvent` / `updateConfig`（热更新）/ `exportConfig`

#### 4.5.2 M2：视图接入（`MachineVpoView.vue` + `MachineVpo3DView.vue`）

- 两个视图组件均引入 `useAnimationConfig('podopener')`
- `onMounted` 调用 `loadConfig()`
- 事件到来时调用 `getPhaseByEvent(eventName, flowType)` 获取阶段信息
- 通过 `getAnimation(animKey)` 拿到动画参数（target / action / axis / from / to）
- 通过 `getTarget(targetKey)` 拿到对应视图的部件引用（SVG id 或 Group 名）
- 2D 视图用 SVG 元素 transform，3D 视图用 Three.js Group position/rotation

#### 4.5.3 M3：调试面板（`EventAnimationDebugger.vue`）

挂在 `MachineDetail.vue` 右侧第 6 个 Tab「调试」上，5 个子 Tab：

| 子 Tab | 功能 |
|--------|------|
| 时间轴 | A. 事件/阶段/动画三轨时间轴 + D. 偏差检测 |
| 事件列表 | B. 实时事件日志（期望阶段 vs 实际阶段） |
| 手动触发 | E. 点击事件按钮立即触发动画 + 直接跳转阶段 |
| 配置编辑 | F. 热编辑阶段 `duration_ms`、事件→阶段映射，导出 JSON |
| 动画录制 | G. 拖拽部件录制关键帧，自动生成动画原语 |

**事件接口**（向父组件 emit）：

- `trigger-event`：手动触发事件
- `jump-to-phase`：跳转阶段
- `config-updated`：配置热更新通知

### 4.7 实时通信（WebSocket + DB Poller）

#### 4.7.1 WebSocket 端点

- 路径：`ws://localhost:8002/ws/realtime`
- 后端：`services/realtime.py` 的 `manager` 单例管理连接
- 前端：`useWebSocket.js` 自动重连（指数退避）

#### 4.7.2 DB Poller 流程

1. `db_poller.py` 每 1000ms 查询 `DT_EVENT_RAW` 表
2. 比较 `raw_id` 是否有新增（基于 `_last_poll_ts`）
3. 解析 `payload_json`，提取 `event_name` / `event_type` / `lot_id` / `alarm_id` 等
4. 按 `event_name` 分类：`pod` / `process` / `alarm` / `other`
5. 同步更新 `DT_EVENT_RAW_CUR` 表（每台机台最新一条）
6. 通过 `manager.broadcast()` 推送到所有 WebSocket 连接

#### 4.7.3 事件来源

- **WinForm 模拟器**（`winform_simulator.py`）：tkinter GUI，单步/自动/报警，写入 DB
- **EAP/TIBRV 真实事件**（ver2 接入中）
- **内部模拟器**（`simulator.py`，默认关闭）

## 五、关键流程

### 5.1 实时事件流

```
1. WinForm 模拟器点击「POD_PLACED」按钮
2. 写入 DT_EVENT_RAW 表（含 payload_json）
3. db_poller.py 1 秒内轮询到新 raw_id
4. 解析 payload → { event_name: 'POD_PLACED', category: 'pod', ... }
5. WebSocket 广播到前端
6. MachineDetail.vue 收到事件 → events.value.unshift(event)
7. MachineVpoView.vue / MachineVpo3DView.vue watch events
8. useAnimationConfig.getPhaseByEvent('POD_PLACED', 'PACKING')
   → { phase: 'POD_PLACE', anim: 'pod.enter', phaseIndex: 0 }
9. getAnimation('pod.enter') → { target: 'podShell', action: 'translate', axis: 'y', from: -400, to: 0 }
10. getTarget('podShell') → { view_2d: 'pod2dLayer', view_3d: 'podShellGroup' }
11. 视图执行动画（SVG transform 或 Three.js position.y）
```

### 5.2 历史回放

```
1. 用户在 PlaybackBar 选择日期 2026-07-15
2. 前端调用 GET /api/history/PODOPENER-1?date=2026-07-15
3. 后端 history.py 查 DT_EVENT_RAW where event_ts_utc BETWEEN '2026-07-15 08:00' AND '2026-07-15 20:00'
4. 返回事件列表 + 24h 时间轴聚合
5. HistoryReplay.vue 渲染柱状时间轴
6. 用户点击某事件 → cursor 跳转到该时间戳
7. 播放循环按 speed（0.5x–16x）推进 cursor
8. 每个事件按 cursor 时间触发对应动画（同实时流步骤 7–11）
```

### 5.3 AI 查询

```
1. 用户在 AI 面板输入「PODOPENER-1 昨天有哪些告警」
   （或按麦克风按钮 → Whisper ASR → 文本）
2. 前端 POST /api/ai/query { question, machine_id, mode }
3. ai_mcp.py 按 AI_PROVIDER 路由：
   - local：规则引擎识别「告警」关键词 → 查 DT_ALARM_EVENT
   - openai：构造 prompt 调 GLM-5.2 → LLM 生成 SQL → 执行
   - dify：调 Dify chat endpoint
4. 返回 { answer, sql, jump: { machine_id, timestamp } }
5. AiAssistant.vue 渲染回答 + SQL
6. 若有 jump 字段，显示「跳转回放」按钮 → 切换到回放模式
```

## 七、关键设计决策

### 7.1 配置驱动而非代码驱动

- 所有事件→阶段→动画映射放入 JSON 配置
- 视图组件只读配置，不硬编码业务逻辑
- 新机型接入 = 新增一个 `xxx.json` + 资源文件

### 7.2 2D/3D 配置共用

- 同一份 `podopener.json` 同时驱动 SVG 2D 视图和 Canvas 3D 视图
- `targets` 字段同时声明 `view_2d`（SVG id）和 `view_3d`（Group 名）

### 7.3 双模式实时驱动

- 内部模拟器（Demo）+ 外部 DB 写入（生产）并存
- 都通过 `DT_EVENT_RAW` 表 + `db_poller.py` 中转
- 切换只需改 `config.py` 两个布尔值

### 7.4 降级策略

| 组件 | 主选 | 兜底 |
|------|------|------|
| 数据库 | Oracle 19c | SQLite |
| 缓存 | Redis | 内存 dict |
| AI | Dify/n8n/LLM | 本地规则引擎 |
| ASR | faster-whisper | 文本输入 |
| 实时事件 | TIBRV（ver2） | WinForm 模拟器 |

### 7.5 时间戳统一

- 所有时间戳统一为东八区本地时间（无 Z 后缀）
- `db_poller.py` 的 `_normalize_ts` 去除 Z 和时区偏移
- 前端 `parseTs` 兼容带 Z 的历史数据
