# FabTwin Pro 项目计划说明书

## 一、项目目标

### 1.1 总体目标
构建半导体工厂数字孪生平台，实现：
- 机台实时监控与状态可视化（支持VPO/OXE/DRM多机型）
- 历史数据回放与趋势分析
- 楼层平面图标注与3D模型集成
- OHT天车调度可视化
- AI辅助查询与智能分析

### 1.2 阶段目标

| 阶段 | 目标 | 交付物 | 当前状态 |
|------|------|--------|---------|
| Demo验证 | 核心功能验证，展示可行性 | 可运行的数字孪生平台 | ✅ 已完成 |
| 机台Vue化接入 | VPO/OXE/DRM机台Vue组件化 | MachineVpoView/MachineVpo3DView/MachineIsoView | ✅ 已完成 |
| 真实数据接入 | 替换模拟数据，接入Oracle和TIBRV | ODS同步管道 | ⚠️ 进行中 |
| 3D模型规范化 | 替换代码模型，使用Blender GLB模型 | 标准3D模型库 | ⚠️ 进行中 |
| AI能力升级 | 接入LLM，实现智能分析 | AI查询系统 | ⚠️ 进行中 |
| 生产级部署 | 优化性能，稳定运行 | 生产环境部署 | 📋 待开始 |

#### 2.3.2 AI架构设计

```
用户提问 → FastAPI → AI中间件 → 多Provider支持
                         ↓
                    ┌─────┴─────┐
                    ↓           ↓
              国内API(GLM等)  OpenAI API

                         ↓
                    ┌─────┴─────┐
                    ↓           ↓
              Oracle查询    MES/RCMS/FDC
```

#### 2.3.3 AI配置管理系统（已完成）

**实现内容：**

1. **数据库层面**
   - 创建 `ai_configs` 表：存储全局AI配置（如默认Provider）
   - 创建 `ai_provider_configs` 表：存储各Provider配置（智谱GLM、DeepSeek、通义千问、OpenAI等）
   - 创建 `ai_usage_logs` 表：记录每次AI调用的Token使用量
   - SQL脚本：`sql/create_ai_tables.sql`（手动执行，不在代码中自动创建）

2. **后端层面**
   - `backend/models.py`：定义三个AI相关的ORM模型
   - `backend/database.py`：修改 `init_db()` 函数，排除AI表自动创建
   - `backend/routers/ai.py`：新增配置管理API端点
   - `backend/services/ai_middleware.py`：统一AI调用接口，支持多Provider切换

3. **前端层面**
   - `frontend/src/components/AIConfigPanel.vue`：AI配置管理面板
   - 功能：配置增删改查、启用/禁用、默认Provider设置
   - 位置：放在用户管理页面旁边
   - Token使用统计：按Provider分布、每日统计

4. **数据库脚本优化**
   - `sql/init_oracle_db.sql`：精简初始化脚本，从24087行减少到204行关键INSERT
   - 移除冗余数据：630条ALARMS、11978条MACHINE_EVENTS、10080条CHAMBER_SNAPSHOTS等
   - 保留关键数据：机台模型配置、事件-动画映射、楼层布局等
   - `sql/init_oracle_aqua.sql`：同步更新，兼容Aqua Data Studio

**关键特性：**
- 支持国内外多种AI Provider（智谱GLM、DeepSeek、通义千问、OpenAI等）
- 配置持久化到Oracle数据库，重启不丢失
- 响应显示当前Provider和Model
- 悬浮窗口支持模型切换下拉菜单
- Function Calling自动降级（不支持的Provider自动重试）
- Token使用量实时统计与可视化
